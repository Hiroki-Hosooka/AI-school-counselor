## 1. 第1部 不具合

### 1-1 チップの選択が正しく受け取られない

#### 1-1-1 原因(仮説。ログで確かめたい)

**状態の保存が、だまって失敗していた**と考えている。

- 固定の文面を出すターンで、route.ts は `sessions` に次の状態を書く(`db.from("sessions").update({...plan.nextState})`)。
  **このとき、エラーを確かめていない。** 失敗しても、生徒には返事が出て、状態だけが前のまま残る。
- 7ターン目のあと、状態が「3通目への答えを待っている(`step3`)」のまま残ると、次のことが起きる。
  - 押したチップは、`validateChoice` が「直前に出した組」を状態(`pending_choice_set`)から読むので、受け付けられない。
    そのため、**ラベルの文字が自由記述として扱われ**、3通目への答えの判定(軽いモデル)にかかる。
  - B2 のラベル「人とつながるのはおっくう…」は「話したくない」と判定され、組Bを出した記録も残っていないので、
    **7ターン目と同じ文と組Bがもう一度出る**(8・9ターン目)。
  - 11ターン目の「4 かなりつらい」(スケーリングのチップ)も同じく自由記述として判定され、「どちらでもない」になり、
    **3通目への「どちらでもない」の返事**が出る。
- これをオフラインで再現した(`planSafetyTurn` に「状態が保存されなかった」入力を与える)。8・9・11ターン目の文がログの記述と一致した。

```
T7: そっか、今は話したくないんだね。…選ぶだけでいいよ。 | chips B | next choice_b
T8(保存できた):     教えてくれてありがとう。もう少しだけ聞かせてね。「話せない」って感じるのは…   ← 本来
T8(保存できなかった): そっか、今は話したくないんだね。…                        | chips B   ← ログと同じ
T9(保存できなかった): そっか、今は話したくないんだね。…                        | chips B   ← ログと同じ
T11(保存できなかった): うん、すぐに決めなくて大丈夫だよ。…                                  ← ログと同じ
```

- 10ターン目(B1 を押したのに返事が無い)は、この仮説だけでは説明できていない。ログの10ターン目の行(flags・エラー)を見たい。
- 保存が失敗した理由はまだわからない。候補は、本番の DB の制約が古い版のまま(`sessions_crisis_state_check` に
  `choice_b`・`scaling` などが入っていない)こと。14節の列は読めている(読めなければ第1段階の動きになり、チップは出ない)ので、
  列はあるが制約だけ古い、という形が一番あやしい。

#### 1-1-2 直し方

1. **状態の保存の失敗を見逃さない。** すべての `sessions` の更新でエラーを確かめ、失敗したら1回やり直し、それでも駄目なら
   その返事の `messages.flags` に「記録のみ:状態の保存に失敗(エラー文)」を残し、サーバのログにも出す。
2. **チップの受け取りを、状態ではなく会話の記録から決める。** 直前の AI の返事の行には、出したチップ(`messages.choices`・
   `choice_set`)が保存されている。新しい関数 `resolveChoice(直前のAIの返事, 送られた choice_id, 書いた文字)` で、
   - 送られた `choice_id` が、直前の返事のチップにある → そのチップ(`button`)
   - `choice_id` が無くても、書いた文字がチップのラベルと同じ(空白・記号・全角半角をそろえて比べる)、または
     数字の組(つらさ・スケーリング)で数字だけ → そのチップ(`typed`)
   - それ以外 → 自由記述
   とする。危機の流れの組(W・B・C・スケーリング)、会話の流れの組G、新しいインテークの組(つらさ・なりたい姿)の
   **すべてを、この1つの関数で受け取る**。状態(`pending_choice_set`)とずれていたら、記録の側を正とし、ずれを flags に残す。
3. **同じ固定の文を、1回の会話で2回出さない(仕組みとしての保証)。** 固定の文面を出す直前に、その会話の AI の発言に
   同じ文があるかを確かめる。あれば、その吹き出しは出さない。出す吹き出しが1つも残らなければ、
   **危機の状態の指示つきの生成に切り替える**(今の `crisisGeneration` と同じ扱い。通知・記録は今どおり)。
   状態が壊れていても、この確かめは会話の記録だけで働く。
   - 気持ちのスケーリングは1回の会話で2回まで出せる決まりなので、2回目の問いの文を別に用意する(仮)。
   - 生成失敗の固定の返事は、今も回数で順に替えているので、そのまま(同じ文は出ない)。
4. **返事が出ないターンを作らない。** 返す直前に、返事の本文が空(空白だけを含む)なら、場面ごとの固定の一言に置き換え、
   flags に「記録のみ:返事が空」を残す。画面でも、応答に返事が無ければ送れなかったときの文を出す(今は何も出ない形がありうる)。
5. **ラベルをそろえる。** スケーリングのチップを、インテークのつらさと同じにする:
   1 少し気になる / 2 まあまあモヤモヤする / 3 かなりつらい / 4 限界に近い / 5 もう耐えられない
   (段階を下げる条件「1か2」「1」は数字で決めているので、数字の意味は変わらない。ラベルの文だけ変わる)。

#### 1-1-3 確認に使う SQL(読むだけ。Supabase の SQL エディタで実行してほしい)

### 1-2 インテークの答えとチップの選択を、危機の判定にかけない

- 1-1-2 の `resolveChoice` でチップ(押した・同じ文字を打った)と判定したターンは、**どの組でも**分類器にかけない
  (今の `assessFlowChoiceTurn` と同じ形。段階はそのまま、状態だけ進める)。
- インテークのつらさ・なりたい姿のターン(2章)で、数字やラベルで答えた場合も同じ(チップとして扱われるため)。
- **2ターン目(きっかけ・背景)の自由記述と、チップ以外の文章は、今までどおり判定にかける。**
- つらさに数字ではなく文章で答えたとき(「正直しんどい、夜も眠れない」等)は本人の言葉なので、判定にかける。
- 分類器のプロンプト(v2・v3)は変えない。判定にかける前の振り分けだけで対応する。

### 1-3 本人の断りを覚える

- 会話の状態に `declined_people`(断った相手。`teacher` 先生・担任 / `parent` 親・おうちの人 / `counselor` カウンセラー /
  `nurse` 保健室)を足す(16節の列)。
- 見つけ方は**コードの照合**を主にする:相手の語(先生・担任・親・母・父・おうちの人・家の人・カウンセラー・保健室 など)と、
  断りの語(話したくない・言いたくない・話せない・無理・いや・やだ・信用できない など)が同じ文にあるとき。
  3通目への答えの判定(`judgeTeacherAnswer`)にも「断った相手」を返させ、照合で拾えなかったものは**推定**として足す(記録で区別)。
- 一度断った相手は、その会話のあいだ覚えている(本人が自分から「先生なら話せるかも」と言ったら外す)。
- **固定の文**:相手を名指ししている文(3通目・「どちらでもない」への一言・2回目の短い1通・本番の固定応答の窓口の段落)を、
  断った相手を含まない版でも組めるようにする(相手の一覧から外して文を組み立てる。文面は仮)。
  例:「下にのせた相談先や、まわりの大人に話してみたいって思う？」(先生・おうちの人を断った場合)。
- **生成**:断った相手があるターンは、「相談者は〇〇には話したくないと言っています。〇〇を勧めない(否定もしない)」を指示に足し、
  出力チェックで〇〇を勧める言い方(〇〇に話してみ・〇〇に相談・〇〇に伝え 等)を見つけたら作り直す。

### 1-4 AIから会話を終える事故

- 出力チェックに「終わりの形」を足す:本人が終わりの合図を出していない(`closing_state` が `asked`/`close` でなく、
  このターンの発言にも終わりの語が無い)のに、AI の返事が
  - 問い(?)も、次につながる一言も無く、
  - 終わりの言い回し(今日はゆっくり休んで・また話そう・またね・また来てね・おやすみ・今日はここまで 等)を含む
  とき、作り直す(1回)。作り直しても残れば、終わりの言い回しを含まない固定の一言(仮)を足す。
- `messages.flags` に「AIから終える形→作り直し」を残し、管理画面で回数を数えられるようにする。
- 本人が終わりの合図を出したときの区切り(5.15・5.6)は、今までどおり。

### 2-3 インテークの流れ(コードの状態で進める)

| 2 | 背景を書く | 判定にかける。次は「つらさ」 | 短い受け止め(1文)だけ。**問いは書かない**(コードが続けて問いとチップを出す) |
| 2→3 | — | 受け止めのあとに、固定の問い(仮)「今、そのことで感じているつらさに近いのはどれかな?」+ つらさのチップ | — |
| 3 | チップ(または数字・ラベルを打つ) | 記録。分類器にかけない。4・5なら、そのターンに「つらさが高い」の指示を付ける(Q7) | 短い受け止め(1文) |
| 3→4 | — | 受け止めのあとに、固定の問い(仮)「今日話していく中で、どうなれたらいいかな?」+ なりたい姿のチップ(吐き出したい/一緒に整理したい/どっちも/まだわからない)。4・5のときは次のターンに回す | — |
