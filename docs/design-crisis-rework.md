## 第1部 安全上の急ぎ(設計。確認待ち)

### 1-1 秘密の約束を止める

- いまの `OUTPUT_NG`(`src/safety.mjs`)には「誰にも言わない」「秘密にする」等があるが、「言いふらしたりはしない」が抜けていた
  (86130eef 10/15〜10/21 T10。このログはまだ受け取っていない)。
- 次の形を `OUTPUT_NG` に足す(どの場面でも禁止。D7):
  - 言いふらさない・言いふらしたりしない
  - 誰にも(言わ|話さ|伝え|ばらさ)ない ※「誰にも言わないで抱えてきた」のような、本人の行動をなぞる「〜ないで」は通す
  - 秘密に(する|しておく)・秘密(は|を)守る
  - 内緒に(する|しておく)
  - ここだけの(話|秘密)にする
  - (ほかの人|ほかの誰か|先生|親)には(言わ|話さ|伝え)ないよ・ないから
- 当たれば、今のしくみどおり作り直す。作り直しても残れば、その場面の固定の一言にする。
- 危機のあとの指示(`AFTER_CRISIS_BLOCK_PROVISIONAL`)と危機の状態の生成の指示に、次の1行を足す:
  「秘密を守ると約束しない(言いふらさない・誰にも言わない・ここだけの話、など)。AI ができないことを約束しない」
- 確かめるのは `scripts/test-output-check.mjs`。止める文と、通す文(「誰にも言えなかったんだね」「誰にも言わないで抱えてきたんだね」)の両方を足す。

### 1-2 429 とプレビュー版のモデル

**ログからわかったこと**

- 55932e90 の T12〜T16 では、フォールバックの最後の `gemini-3-flash-preview` まで全部 429 になっていた。
- 1つのモデルの問題ではなく、キー(プロジェクト)の上限に当たっている。
- エラー文の「You exceeded your current quota, please check your plan and billing」は、次の2つの場合に出る:
  - 無料枠を使い切ったとき
  - 有料でも、プロジェクトの使用上限やレート上限に当たったとき

**本番のモデル**

- テスト用キーで提供中のモデルを一覧した(2026-11-01)。
- 番号つきの安定版名(`-001` のように版を固定した名前)は、Gemini 3.x の flash には無い。
- 安定版として出ているのは `gemini-3.8-flash`・`3.7-flash`・`3.6-flash`・`3.5-flash` で、`gemini-3-flash-preview` はプレビュー版。
- そこで、本番の `PRIMARY_MODELS` からプレビュー版を外し、安定版4つだけにする。
- 分類器の `LITE_MODELS` は `gemini-3.5-flash-lite`・`gemini-3.1-flash-lite` で、どちらも安定版のため変えない。

**1回の呼び出しに時間の上限を付ける(前回の提案)**

- 1つのモデルの呼び出しが、8秒(分類器は5秒)を超えたら打ち切って次のモデルへ移る。
- 返事に 30秒〜4分かかっていた原因の一つが、上限の無い待ちだったため。
- どのモデルを試して、それぞれ何で失敗したか(429・時間切れ・ブロック)を `messages.flags` に残す。

**キーの上限と課金の確認(人の作業)**

本番のキーは私からは見えません。Google AI Studio で次を確かめてください(キーをチャットに貼らないでください)。

1. 本番の `GEMINI_API_KEY` がどのプロジェクトのキーかを確かめる。AI Studio の「API キー」で、Vercel の値の末尾4文字と照らす。
2. そのプロジェクトの「使用量と課金」で、次の3つを見る:
   - 料金の階層(Free / Tier 1 以上)
   - 課金アカウントがつながっているか
   - 使用上限(spend cap)を設定しているか
3. 「レート上限」の画面で、使っているモデルごとの上限(1分の回数・1日の回数)を見る。

- Free のままなら、5.10(無料枠は生徒の会話に使わない)に反している。課金アカウントをつなぐか、有料のプロジェクトのキーに替える必要がある。
- 有料でも 429 が出ているなら、使用上限の金額か、Tier の上限が原因。

**近づいたことに管理画面で気づく(案)**

- 管理画面(admin.html)の一覧の上に、直近1時間と24時間のモデルの状態を1行で出す:
  - 返事の数
  - 429 の回数
  - フォールバックした回数
  - 固定の一言で受けた回数(生成の失敗)
  - 返事にかかった時間の中央値
- 数字は `messages.flags` と `messages.timings` から数える。新しいテーブルは作らない。
- 直近1時間の 429 が3回を超えたら、その行を警告の色にする。
- あわせて、`CRISIS_WEBHOOK_URL` に「429 が続いています(直近1時間 n回)」とだけ送る。1時間に1回まで。
  - 相談の本文もセッションIDも含めないので、5.3 に沿う。
  - いらなければ外します。
- 補足: Google 側の「残りの枠」を直接読む API は無いので、こちらで数えた失敗の回数で代わりに見る。

### 1-3 危機の種類ごとの受け止めと窓口(仮・心理士の確認待ち)

**種類**(1つの発言に複数あってよい)

| 種類 | 見つけ方 |
|---|---|
| 本人の希死念慮 `suicidal` | 今のキーワードの種類 |
| 本人の自傷 `selfharm` | 今のキーワードの種類 |
| 本人が受けている暴力・虐待 `abuse` | 今の `violence`・`sexual` に、家での暴力を見ている(面前DV)語を足す。例: 「父が母を殴る」「親がけんかで物を投げる」 |
| 第三者の危機 `other` | 分類器の `subject=other`。加えて、同じ節に家族・友達の語と危機の語(自殺未遂・OD・死にたいって・リスカしてる 等)がある照合 |

- 1d0a0511 15:18 では、母の「自殺未遂」を本人の希死念慮として数えていた。
- 第三者の照合に当たった危機の語は、本人の希死念慮には数えない。

**受け止めの一言(今の固定応答の「〜が、とても心配です」の部分)**

| 種類 | 一言(仮) |
|---|---|
| suicidal | いなくなりたいと思うくらい、つらい気持ちがあること(今のまま) |
| selfharm | 自分を傷つけてしまうくらい、つらい気持ちを抱えていること(今のまま) |
| abuse | 家で暴力を受けたり、目の前で見たりしていて、あなたの安全が守られていないかもしれないこと |
| other | 身近な人のことを、あなたがひとりで心配し続けていること |

- 種類が2つ以上のときは、優先の順(abuse > suicidal > selfharm > other)で2つまでを「〜こと、それから〜こと」とつなぐ。
- 第3部で受け止めを生成に移すときは、この表を「場面ごとの指示」に替える。窓口のカードは固定のまま残す。

**窓口のカード(種類ごと。仮)**

| 種類 | 並び(上から) |
|---|---|
| abuse | **189 児童相談所虐待対応ダイヤル**・24時間子供SOSダイヤル・チャイルドライン・いますぐ危ないとき 110 / 119 |
| suicidal | 24時間子供SOSダイヤル・チャイルドライン・よりそいホットライン・こころの健康相談統一ダイヤル・いますぐ危ないとき 119(今のまま) |

- 複数のときは、優先の順で並べ、重複を除く。189 は abuse があれば必ずいちばん上に置く。
- サーバが応答に `crisis_types` を付け、画面はそれに合わせてカードを組む。カードの番号は今と同じく `page.tsx` の固定データに置く。

- 第三者だけのとき(本人の危機ではない)は、今どおり生成で受ける(5.12)。カードを添えるかは、次の質問2で決めていただきたい。
- 記録として、`safety_events` に種類の並びを残す。列は足さず、`reason` に「types: abuse,other」の形で書く。
