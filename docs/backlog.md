## P1 — チューニングを回せるようにする

### 1-1. ナレッジ管理画面

Supabase の Table Editor は英語UIなので、心理士の方には使ってもらえません。

**必要な機能**
- 一覧（出典・種別・重心でフィルタ）
- 本文の編集、`active` の切り替え（**削除はさせない**）
- 新規追加（`src` `school` `cat` `weight` `tags` 必須）
- `knowledge_history` の閲覧

**完了の条件**
- カウンセラーが自分で1件編集でき、1分後に応答へ反映される
- 誤って原則を全部消せないようになっている
- 簡易的でよいので認証がある（生徒がアクセスできない）

---

### 1-2. 会話ログのレビュー画面 ✅ 完了(実装済み・要ユーザー確認)

心理士との検討会で、印刷ではなく画面で1行ずつ潰せるようにする。

**必要な機能**
- セッション一覧 → 会話の再生
- 各AI応答に、そのターンの `relation` / `question_level` / `role` / `weight` / `hypothesis` / `used` を並べて表示
- 1〜5の評価とコメントを入力（`messages.rating` / `rating_comment`）

**完了の条件**
- 「なぜこの返答になったか」が画面上で追える
- 評価が保存され、`knowledge_score` ビューに反映される

**実装内容**
- `public/admin.html`(単一HTML・ビルド/外部パッケージ不要)を新規作成。生徒側の `page.tsx` は未改変
- `src/app/api/chat/route.ts` に `admin_sessions`(一覧。`db/schema.sql` の `session_overview` ビューを利用)と
  `admin_session_detail`(詳細。メッセージ+参照ナレッジ本文を結合)を追加
- 認証はログイン画面ではなく `ADMIN_TOKEN` とのURLクエリトークン照合(プロトタイプ判断。README参照)
- 評価保存は生徒側と同じ既存の `rate` アクションをそのまま利用(変更なし)

**ユーザー側でまだ確認できていないこと**
- Vercelに `ADMIN_TOKEN` を設定し、実際のデータで一覧・詳細・評価保存が動くこと
- `db/schema.sql` を再実行し `session_overview` ビューが作成されていること(0-1 のSQL再実行に含まれる)

---

### 1-3. 機械だけで測る自動テスト一式(Gemini前提) ✅ 実装済み(実データでの実行はこれから)

生徒役のAIと会話させ、ログを溜める。ナレッジやプロンプトを変えたとき、
悪化していないかを人手を介さずに確認するため。詳細仕様は
`docs/prompts/automated-testing-harness.md` を参照(実施メモも同ファイルに追記)。

**構成する4本柱(すべて実装済み)**

1. **危機検知の精度** — `npm run test:crisis`。ラベル付き発話セットに対する適合率・再現率・F1、
   および Gemini 安全フィルターによるブロック率を分けて集計する(`src/classify.mjs`)
2. **禁止表現の漏れ率** — `npm run test:ng-leak`。同一入力を複数回投げ、出力チェックの検知率を測る
3. **関わりの型判定の安定性** — `npm run test:relation-stability`。同一シナリオを繰り返し、
   判定のぶれを見る
4. **ペルソナ多ターン回帰テスト** — `npm run test:persona-regression`。生徒役(Flash-Lite)×
   評価対象(PRIMARY_MODELS)。`sessions`/`messages`に保存し`admin.html`から閲覧できる

ナレッジ検索・システムプロンプト構築・本生成は `src/generate.mjs` に切り出し、
route.ts(本番)とテスト2〜4が完全に同じ関数を使う(測定対象と本番実装がずれないため)。

**モデルの使い分け(Gemini)**

| 役割 | モデル | 枠 |
|---|---|---|
| 生徒役ペルソナ | Flash-Lite(`LITE_MODELS`) | 無料枠(`TEST_GEMINI_API_KEY`) |
| 評価対象(相談AI本体) | `PRIMARY_MODELS`(本番と同じFlash系) | 無料枠(`TEST_GEMINI_API_KEY`) |
| 危機判定・分類 | Flash-Lite(`LITE_MODELS`) | 無料枠(`TEST_GEMINI_API_KEY`) |

「Pro」は現状 `PRIMARY_MODELS` に含まれていない(実在未確認のモデルIDを推測で
書かないため)ため採用していない。品質面での「本番相当」は、本番と同じ`PRIMARY_MODELS`を
使うこと自体で満たしている。用途による枠の分離(無料枠は合成テスト専用)は
モデルの品質とは別の軸なので、テスト対象がFlashでもProでも `TEST_GEMINI_API_KEY` を使う。

**守ること(CLAUDE.md 5.10 / 5.11 と対応)**

- 無料枠は合成テストにのみ使う。本番環境の環境変数・APIキー(`GEMINI_API_KEY`)とは
  完全に分離する(テスト専用の `TEST_GEMINI_API_KEY` を使う)
- 危機系ラベル付きセットを流すときは、**精度と別に「ブロックされて無応答だった件数」を必ず集計する**
- 安全フィルターの閾値を緩めた場合、その判断とブロック率の実測値をセットで記録する

**テスト4の安全上の配慮(route.ts本体・DBスキーマは変更していない)**

- `client_id` を `TEST-PERSONA-<ペルソナ>-<実行時刻>` にし、`admin.html` の一覧で
  実際の生徒(匿名UUID)と見た目で区別できるようにした
- 危機分岐時、会話には固定応答(`CRISIS_REPLY`)を残すが、`notifyCrisis()` の呼び出しと
  `safety_events` への書き込みは行わない。合成ペルソナの発言で実在しない生徒の危機が
  学校スタッフに誤通知される事態を避けるため
- `person_memory` は更新しない(一回きりの合成会話のため)

**完了の条件**

- ✅ 5〜6種類のペルソナ(ビジター型／コンプレイナント型／短文だけ返す子／作戦会議まで進む子など)
- ✅ 1コマンドで全ペルソナ×10ターンを回してログをDBに保存
- ✅ 実行時のナレッジ世代(`sessions.knowledge_version`)が記録されている
- ✅ 危機検知の適合率・再現率・F1・ブロック率の4指標がレポートに出る(テスト1)
- ✅ レート制限に当たった場合、エラーで落ちずに間隔を空けて再試行する
- ⬜ 実際のキー・DBでの実行と、結果の確認(ユーザー側の作業)

> **評価AIのスコアを信用する前に、心理士の採点20件と突き合わせること。**
> 一致率を測らずにスコア推移を見ても意味がありません。

## やらないと決めたこと

理由つきで残します。蒸し返さないため。

| やらないこと | 理由 |
|---|---|
| ログイン機能 | 敷居を下げることが目的。登録を求めた時点で構造が壊れる |
| 危機時のリスクアセスメント | 対面・訓練・接続先があって初めて成立する。AIがやると方法を語らせる会話になる |
| 通知への本文添付 | 未成年の相談内容をチャットツールに流さない |
| FastAPI・別サーバーの追加 | Next.js の Route Handler で足りる。デプロイ先を Vercel + Supabase の2つより増やさない |
| ビルド工程の導入 | **撤回(2026年9月)**。単一HTML構成だったが、VercelへのフルデプロイのためNext.jsに全面移行し、ビルド工程を前提にした。理由つきで残すのは、この撤回自体を蒸し返さないため |
