# 会話が展開しない問題の修正(設計)

2026年10月11日。指示書「会話が展開しない問題の修正」(`docs/prompts/conversation-flow-fix.md`)と
「『他人事感』の修正」(`docs/prompts/conversation-engagement-fix.md`)に対する設計。
**第1部(0〜10章)は人が確認済み(11章に回答)。第2部(12章〜)は確認待ち。両方の確認が取れるまで実装しない**
(第1部の部品 `src/flow.mjs` は下書きとして置いてあるが、まだどこからも使っていない)。
材料は相談ログ 16f362dd(`docs/review-logs/2026-10-11-16f362dd.md`)。

危機の流れ(段階2の固定の文面・チップ)、安全層(`CRISIS_WORDS`・`OUTPUT_NG`・危機の分岐)、通常の状態の分類器(`CLASSIFIER_PROMPT_V2`)には触れない。
1回の返事で問いは1つまで、は変えない。

## 0. ログを読んで確かめた原因

| 原因 | コードの箇所 | 確かめたこと |
|---|---|---|
| 「迷ったら問わずに受け止めだけ」が効きすぎ | `src/generate.mjs` `PHASE2_FLOW_BLOCK` | 文面どおり。9〜12ターンはすべて question_level = none |
| コンプレイナントの読み違い | 同上「complainant: …本人に行動を求めない。」 | 「問わない」との区別がどこにも書かれていない |
| V4・V5 が引かれていない | `retrieve()` | V4・V5 のタグは「せいで・あの子・悪い・ひどい・変わってくれない」など。ログの言葉(一人・誰もやってくれない・なんのため)に当たらない。コンプレイナントで足しているのは S2 の +4 だけ |
| まとめが来ない | `buildSystem` の区切りの指示 | 区切りの促しは「前回から6ターン以上」のときだけ。8ターン目の「整理してみたい」は、`did_summarize` の確かめが無いので素通り |
| ゴールが使われない | `buildSystem` | `user_goal` を読んでいるのは `buildClosingBlock` だけ。フェーズ2の毎ターンのプロンプトに入っていない |
| モードの最初の一手が出ない | `buildModeBlock` | CBT の進め方は載っているが、「いつまでに一度は使う」という決まりが無い |
| 強い言葉の上乗せ | 「相手の言葉をそのまま使って返す。言い換えすぎない。」 | 指示はあるが、確かめる仕組みが無い |

**12ターン目(「なんで頑張ってるのかわからない」)の段階**:本番の記録はこの環境から読めないので、同じ文脈(直前の会話つき)で
通常の状態の分類器(無料枠のテスト用キー・合成の再生)に3回かけた。**3回とも段階1(watch。根拠は分類器 `classifier_watch`、キーワードの当たりなし)。**
理由は「頑張る理由が分からず無力感がある」。11ターン目(「虚しいというか虚無になる…」)も3回とも段階1。
本番で実際にどう記録されたかは、管理画面(このセッションの `safety_events`)で確かめてほしい。段階1なら、11・12ターンの返事には Tier B の指示が付いていたことになる。
(段階1でも、出来事・気持ち・望みを聞く問いはしてよい。しないのは危険度を確かめる問い。1-4)

## 1. 受け止めだけの返事を続けない

### 1-1 プロンプト(`PHASE2_FLOW_BLOCK`)

- 「迷ったら下の層に留めるか、問わずに受け止めだけにする。」を、指示書どおり
  「迷ったら、問いの層を下げる(事実や本人の感じ方を聞く問いにする)。問わないことを選ぶのは、相談者がそれを望んだとき、または直前に問いを重ねすぎたときだけ。」に替える
- 「問わず受け止めのみ(none)は続けて2回まで。3回目は、問い(1つ)・まとめ・進め方を選んでもらう選択肢のどれかにする」を足す
- 「次につながる一言」(IS4)の指示を強める:問いでない返事でも、最後に相談者の直前の言葉を使った手がかりを置く。
  「その気持ち、もう少し聞かせてもらえる?」のような汎用の一言だけを毎回付けない
- 問いは出来事・考え・気持ち・望みを聞くもの。危険度を確かめる問いはしない(5.2)。段階1以上でも同じ

### 1-2 サーバが数える

- 直前までの AI の返事の `question_level` を `messages` から数え、「いま受け止めのみが何回続いているか」をプロンプトに渡す
  (列は足さない。`messages.question_level` はすでにある)
- 2回続いているときは、そのターンだけ「★ 受け止めだけが2回続いています。この返事は問い・まとめ・選択肢のどれかにする」を出す
- 数えるのは生成した返事だけ。危機の流れの固定の文面・チップは数えない(対象外)
- 傾聴のモード(LISTEN_ONLY)、または相談者が「聞いてほしいだけ」と言ったときは、★を出さず「問いを減らしてよい。ただし次につながる一言は必ず付ける」にする
  (「聞いてほしいだけ」はモデルが申告する。`listen_only_requested`。そのセッションで一度立ったら残す)

### 1-3 出力チェック(作り直し1回)

- モデルが question_level = none と申告し、返事に「？」が無く、受け止めのみが3回目になる → 1回だけ作り直す(上の★の指示を強めて)
- 作り直しても同じなら、そのまま出して `messages.flags` に記録する(会話は止めない)
- 傾聴のモードのときは作り直さない(記録だけ)

## 2. コンプレイナント型

- `PHASE2_FLOW_BLOCK` の complainant の行を
  「本人に行動を求めない。**ただし、行動を求めないことと、問わないことは別。** 出来事(『そう感じるエピソードがあったの?』)や、本人の望み(『その時、どうしてほしかったの?』)を聞く問いは使う」にする
- `retrieve()` で、関わりの型が complainant のとき V4・V5 に +4(今の S2 と同じ足し方)。タグに当たらなくても候補に入る
- 「本人の見方が狭まっている言葉(『自分しかできないし誰もやってくれない』など)を、AI が強める形で返さない。出来事を聞くか、本人の望みに角度を変える」を足す(5.1 の同調の禁止と同じ向き)

## 3. まとめを、実際に行う

### 3-1 いつ

- これまでどおり、前回の区切りから6ターン以上
- 加えて、相談者が意味を見失った言葉を出したとき、モデルに申告させる(`lost_meaning`。「わからない」「なんで〜してるのか」「何のために」など)。
  立ったら次の返事でまとめを提案する(★の指示)。キーワードで機械的に決めるのではなく、プロンプトの例として渡す
- AI が「整理してみたい」「まとめてみたい」と言ったら、そのターンでまとめる(プロンプトの決まり+出力チェック。下の3-3)

### 3-2 まとめの形(T16・IS8)

1. 「一回まとめてみるね」と断る(または一言たずねる)
2. 相談者の言葉を使って、出てきたことを2〜4個並べる
3. 「合ってるかな?」と確かめる
4. 「ここまで話してみて、何か感じたことってある?」(T16)

**確認したいこと**:2の「合ってるかな?」と4の問いを同じ返事に入れると、問いが2つになり「1回の返事で問いは1つまで」とぶつかる。
**案:まとめの返事は「合ってるかな?」で終え、4の問いは次のターン(本人が「合ってる」等と答えたあと)で出す。**
次のターンに4を出すことは、`did_summarize` が立った次のターンだけ、サーバがプロンプトで指示する。

- まとめが要るとき(区切り・意味を見失った言葉・「整理してみたい」)は、IS8・T16 を必ず参照する知識に入れる(今の強制 ID の仕組み)
- AI が結論を言い切らない

### 3-3 `did_summarize` を確かめる

- モデルが `did_summarize: true` と申告しても、返事に「確かめ」(`合ってる|あってる|ずれてない|違ってたら` のどれか)と、並べた項目(読点か改行で区切った2つ以上)が無ければ、
  サーバは false として扱う(`turns_since_summary` を戻さない)。`messages.flags` に「記録のみ:まとめの形を満たしていない」と残す
- 返事に「整理してみたい|まとめてみたい|整理してみよう|まとめてみよう」があるのに、上の形を満たしていなければ、1回だけ作り直す(8ターン目がこれに当たる)

## 4. ゴールとモードを、会話の中で使う

### 4-1 ゴール

- フェーズ2の毎ターンのプロンプトに「インテークで聞いた本人の期待するゴール:{user_goal}」を入れる(`buildSystem`)
- ゴールに「整理」が含まれ、フェーズ2に入ってから吐き出しのターンが3ターン続いたら(まとめ・選択肢が無いまま)、整理に移ることを提案する。
  **提案はチップにする**(組 G。仮・心理士の確認待ち。`src/crisis-response.mjs` ではなく新しいファイル `src/flow-texts.mjs` に置く)
  - 「このまま話したい」
  - 「一緒に整理してみたい」
- 仕組み:モデルが選択肢を出すと申告(`offer_organize: true`)し、サーバが組 G のチップを返事に付ける(文面はモデルに書かせない)。
  押したら、次のターンのプロンプトに「本人は『〜』を選んだ」と渡す。チップを押したターンは分類器にかけない(本人の言葉ではない。5.18 と同じ扱い)。
  チップは押さなくてもよい。1回の会話で2回まで
- `messages.choices` / `choice_set` / `choice_id` の列(14節)をそのまま使う。DB の列は足さない(列が無い本番の DB では、チップを出さずに言葉だけで提案する)

### 4-2 モードの最初の一手

- `buildModeBlock` の各モードに「最初の一手」を足し、「フェーズ2に入ってから3ターン以内に一度は使う。本人が拒んだら続けない」と書く

| モード | 最初の一手 |
|---|---|
| CBT | 出来事・そのときの考え・気持ちを分けて聞く。「その瞬間、頭の中ではどんなことが浮かんでる?」 |
| SFBT | うまくいっている時・例外を聞く。「少しでもましだった日ってあった?」 |
| NARRATIVE | 問題を本人から切り離して呼ぶ(技法名は言わない) |
| LISTEN_ONLY | 問いは減らすが、次につながる一言は付ける |

- 複合モード(「傾聴+CBT」)では、傾聴で受け止めたあと、CBT の一手に移る
- サーバは「フェーズ2の何ターン目か」と「最初の一手をもう使ったか」(モデルの申告 `mode_first_move: true` を `messages.flags` に残し、それを数える)をプロンプトに渡す。
  3ターン目でまだなら★で促す。列は足さない

## 5. 同じ言い回しを繰り返さない

### 5-1 プロンプト

- 受け止めの形を回す:くり返し・言い換え・要約・気持ちの明確化・是認・問い
- 直前2回の返事と同じ終わり方(「〜んだね。」で終わる、など)にしない
- 「ずっと(一人で)頑張ってきたんだね」と同じ意味の受け止め(頑張り・抱え込みへの労い)は、1回の会話で1回まで
- サーバは、直前2回の AI の返事の終わりの一文と、すでに労いを言ったかを、プロンプトに渡す

### 5-2 出力チェック(作り直し1回)— 重なりの測り方と閾値

**ふつうの言葉の重なり(n-gram)は使わない。** ログで測ると、直前3回の返事との 3・4文字の重なりの割合(相談者の直前の言葉に含まれる部分を除く)は
T2 0.14 / T3 0.23 / T4 0.22 / T5 0.05 / T6 0.25 / T7 0.04 / T8 0.18 / T9 0.17 / T10 0.20 / T11 0.22 / T12 0.24 で、
インテークの台本のターン(T3・T6)と見分けがつかなかった。漢字だけの重なりも T11 = 0。**このログのくり返しは、言葉ではなく「意味」と「形」のくり返し。**

そこで、次の3つで測る(フェーズ2の生成した返事だけ。インテークの台本・危機の固定の文面は対象外)。

| 測るもの | 決まり(閾値) | ログで当たったターン |
|---|---|---|
| A 受け止めのみの連続 | 3回目(1-3) | 11・12 |
| B 同じ意味の労い | 返事に労いの形があり、直前3回の AI の返事のどれかにもある | 8・11・12 |
| C 終わり方 | 問いで終わらない返事の、終わりの形(「〜ね」「〜よ」など)が直前2回のどれかと同じ | 11・12 |

- B の労いの形(案):`(ずっと|一人|ひとり|自分だけ|会長だから).{0,14}(頑張|がんば|抱え|背負|踏ん張|耐え)` または `(頑張|背負|踏ん張|耐え|抱え)(って|て|込んで)?(き|来)た`
- A・B・C のどれかに当たったら、どれに当たったかを添えて1回だけ作り直す。作り直しても当たれば、そのまま出して `messages.flags` に記録する
- ログ(2〜6ターン)では、どれにも当たらなかった(インテークを除くと6ターン目だけがフェーズ2で、当たり無し)

**確認したいこと**:指示書は「7〜12ターンが検知されること」。この案で作り直しになるのは **8・11・12**(と、3-3 で 8)。
- 7は、労いの1回目で、問いでも終わっているので当てない(当てると、1回目の労いまで作り直しになる)
- 9・10は、受け止めのみの1・2回目(1-1 の決まりで許している回数)。9は 6章の強い言葉(「取り残され」)で記録には残る
- 7〜12 をすべて作り直しにするなら、「受け止めのみの2回目」も作り直しにする必要がある(=「続けて2回まで」を「1回まで」にすることになる)。この案では、指示書の「2回まで」を優先した

## 6. 相談者の言葉より重くしない

- 「相手の言葉をそのまま使って返す。言い換えすぎない。」を強める:「相談者が使っていない強い言葉(すり減る・限界・逃げ場・取り残され・耐えられない など)を足さない。相談者が『虚無』と言ったら『虚無』で返す」
- **記録のみのチェック**:AI の返事に、下のリストの言葉があり、そのセッションの相談者の発言のどれにも同じ語幹が無ければ、`messages.flags` に「記録のみ:相談者の言っていない強い言葉(〜)」と残す。作り直しはしない。インテークのつらさスケールの選択肢の文(「限界に近い」「もう耐えられない」)は除く

言葉のリスト(案。語幹で照合):

| 確定の案 | 根拠 |
|---|---|
| すり減・限界・逃げ場・取り残・耐えられ | 指示書の例。ログの 9・11・12 |
| 押しつぶ・押し潰・潰れ・追い詰め・ぼろぼろ・ボロボロ・心が折れ・壊れ | 同じ向き(消耗・破綻を言う語) |
| 絶望・孤独・孤立 | 状態に名前を付けて重くする語 |

| 心理士さんに確かめたい候補 | 迷う理由 |
|---|---|
| 苦しい・重い・重荷・背負 | 9ターン「すごく苦しい」、7ターン「重いものを背負って」。ふだんの受け止めにも出るので、入れると記録が増える |

ログに当てると、9(取り残)・11(すり減・逃げ場)・12(すり減)が記録される。
