# 提案:安全フィルターで応答がブロックされたときに、固定の短い一言で受ける

> 2026年10月11日。**設計案だけで、まだ実装していない。文面はすべて仮(心理士さんの確認待ち)。**
> 指示書 next-steps-20261011 3-4。測定の結果は `docs/test-results/safety-filter-20261011-summary.txt`(ブロック 0/303)。

## 1. 今の動き

| 場面 | ブロックされたとき |
|---|---|
| 危機の判定(分類器) | 分類器のエラーとして扱う。キーワードが当たっていれば段階2のまま、当たっていなければ段階1以上(安全側)。生徒の画面は空にならない |
| 本人の危機(段階2) | 固定応答なので生成しない。ブロックされない |
| 本生成(ふつう・危機のあと・気がかり・第三者) | 次のモデルに切り替え → 全部だめなら3秒おいてもう1回 → それでもだめなら生成失敗の固定の返事(`GENERATION_FAILURE_REPLIES`。2種類) |

画面が空になることは今もない。ただし、生成失敗の固定の返事は場面を見ていないので、次の問題がある。

- 1つ目「ごめん、いま自分の方でうまく受け取れなかったみたい。**もう少しだけ聞かせてもらえる?**」は、危機を打ち明けた直後だと、
  打ち明けたことをもう一度言わせる(深掘りに近い)。「受け取れなかった」は、打ち明けが届かなかったように読める(嶋先生 10/7 の「シャッター」に近い)
- 同じ会話で3回目以降の失敗では、2つ目の文がくり返される(やり残しの一覧 2-2)
- ブロック(`[BLOCKED]`)だったのか、レート制限などだったのかは記録されるが、実際のエラー文は本番の DB に残っていない(同 2-2)

## 2. 案

### 2-1 場面で一言を分ける(仮の文面)

生成に失敗したとき、そのターンの安全の文脈(`safetyContext`)を見て、次の一言を出す。

| 文脈 | 一言(仮) | 添えるもの |
|---|---|---|
| 危機のあと(`afterCrisis`) | 「ごめんね、いまうまく言葉が出てこなかった。でも、ここまで書いてくれたことは、ちゃんと受け取っているよ。」 | 危機カード(窓口)をもう一度出す |
| 気がかり(`tierB`) | 「ごめんね、いまうまく返せなかった。しんどい気持ちを書いてくれたこと、ちゃんと受け取っているよ。」 | 気づかいの窓口(折りたたみ) |
| 第三者(`thirdParty`) | 「ごめんね、いまうまく返せなかった。その人のことを心配して書いてくれたこと、ちゃんと受け取っているよ。」 | なし(画面下の常設の窓口はある) |
| ふつう | 今の `GENERATION_FAILURE_REPLIES` のまま | なし |

- 決まり: 打ち明けを言い直させない(「もう少し聞かせて」と言わない)、「受け取れなかった」と言わない、「いつでも」と言わない、
  AI の限界で区切らない(出力チェックの `OUTPUT_NG` と危機の生成の追加チェックも通る文にする)
- 同じ会話で同じ一言を2回出さない。2回目は短い別の一言(仮:「うまく返せなくてごめんね。急がなくていいよ。」)、
  3回目以降は一言を出さず、窓口のカードだけを示す(くり返しで「うるさい」と感じさせないため。9月26日のペルソナテストの教訓)
- **危機の場面では、この一言のあとも窓口の表示が残る**(危機カードを添える。画面下の常設の表示も変えない)

### 2-2 記録と通知

- `messages.flags` に「生成失敗→場面の一言(原因)」を残す。ブロックのときは理由(`SAFETY` 等)も残す
- 実際のエラー文(`failureDetail`)を `safety_events` か `messages.flags` に短く残す(やり残し 2-2 もあわせて直る)
- 危機のあと・第三者でブロックが起きたら、管理画面の「確認待ち」に並べる(職員への通知は今の段階2のときだけのまま。
  通知を増やすかは学校との取り決めで決める)

### 2-3 閾値

測定ではブロックが0回だったので、`BLOCK_ONLY_HIGH` のまま変えない。ただし、分類器への入力のうち10回に
`HARASSMENT:MEDIUM` の評価が付いた(受動的な希死念慮・表記ゆれ・暴力の打ち明け)。Google の既定
(`BLOCK_MEDIUM_AND_ABOVE`)のままなら、これらは止められていた可能性がある。**閾値を既定に戻さないこと**の根拠として記録する。
