## 全体方針

**進み方の骨格は構造化面接のまま採用します。**

```
フェーズ0: 安全確認(全ターン常時・最優先)
フェーズ1: インテーク(4ターンのスロットフィリング)
           Turn1 主訴カテゴリ選択 → Turn2 背景・きっかけ
           → Turn3 つらさスケール → Turn4 期待するゴール
内部アセスメント: recommended_mode を判定(複合可)
           CBT / SFBT / NARRATIVE / ASSERTION / LISTEN_ONLY /
           PROBLEM_SOLVING / PSYCHOEDUCATION (+ MIは横断的技法)
フェーズ2: 判定されたモードのプロトコルに沿って進行
           5〜6ターンごとに区切りの要約を挟む
クロージング: ユーザーが区切りを希望するまでAIから終わらせない
```

**ただし、フェーズ2で「何を話すか」の中身と、応答の言い回しは、
既存の非構造化ナレッジ(嶋/石の逐語)を優先して使ってください。**
`00_統合版...txt` の17章にある技法カタログの例文(「その時と今とで、何が違ったんだろう？」等)
は、あくまで既存ナレッジに該当する逐語が無い場合の補完として使う位置づけです。
既存の逐語(例えば例外探しなら石田先生・嶋先生の該当箇所)がある場面では、
そちらの言い回しを優先してください。

## 確定している設計判断(ここは変更しないでください)

### ① 危機対応:Tier Bの二択質問を、人に言えない障壁を探る形に置き換える

`03_共通グランドルール...txt` の7-2②(Ask)にある、次の質問はそのまま使いません。

> 「それは『消えたい』とか『いなくなりたい』みたいな気持ちに近い？それとも、
> 『このやり方だと変われない』ってもどかしさが強い感じかな？」

これは実質的に、AIが本人に二択で危機の程度を確認させる、リスクアセスメントに相当する
設計です。既存の原則(危機時にAIがリスクアセスメントを行わない。石田先生・嶋先生の
双方の証言により、五感でしか判断できない領域とされているため)と衝突します。

代わりに、嶋先生インタビュー2および石田先生の逐語(V11・V19相当)にある
「人に言えない障壁を探る」アプローチに置き換えてください。

- 二択で危機の程度を確認する質問はしない
- Tier Aの明確なサイン(「死にたい」「消えたい」等)への対応(Tell→Listen→Keep safe)は
  そのまま採用する
- Tier Bに相当する曖昧なサインには、程度を確認する質問の代わりに、
  「なぜ人には言いにくいと感じるのか」を尋ねる方向に倒す
- 危機の内容そのもの(死にたい、という気持ちの中身)を深掘りしない。
  深掘りしていいのは「生身の人に言うことへの障壁」の方だけ
- 一つのメッセージに詰め込まず、複数ターンに分けて出す
  (嶋先生インタビュー2:「一気に情報量がめっちゃ多いから、1個ずつ分割できへんのかな」)

### ② 「絶望感の表現 ≠ 危機サイン」を反映する

現在の `CRISIS_WORDS` には「もう無理」「限界」が含まれていますが、
これらは単独では危機サインとして扱わないでください。
`03_共通グランドルール...txt` の7-1にあるTier A/Bの分類を参考に、
キーワードリストを次のように見直してください。

- Tier A相当(即座に危機対応): 「死にたい」「消えたい」「自殺」等、生命に関わる明確なサイン
- Tier B相当(様子見・確認が必要だが、即座に固定応答へ切り替えない): 「もう無理」「限界」
  「自分なんて」等の無力感・自己否定の表現
- Tier Bが複数ターンにわたって積み重なった場合は、改めてTier Aに近いかどうかを見る

判定ルールの詳細は、7-1の分類ロジックを参考にしてください。ただし、
このロジック自体をAIに毎ターン喋らせる必要はなく、判定はこれまで通り
入力フィルタ(キーワード検知＋分類器)の内部処理として行ってください。

### ③ 全てのモードを実装対象とする(絞り込まない)

CBT/SFBT/NARRATIVE/ASSERTION/LISTEN_ONLY/PROBLEM_SOLVING/PSYCHOEDUCATION の
7つ全てを実装してください。PROBLEM_SOLVINGとPSYCHOEDUCATIONは、まだ
カウンセラーへの取材でナレッジが厚くない領域ですが、`02_専門プロトコル別
ナレッジベース.md` を一次資料として実装し、今後のインタビューで逐語を追加していきます。

### ④ クロージングのルールは、構造化プロンプトの11章をほぼそのまま採用する

`00_統合版...txt` の11章・18章にあるクロージングのルールは、既存の非構造化側の
設計より具体的で優れています。特に次の区別は必ず実装してください。

- 技法上の手詰まり(「思いつかない」「わからない」)を、会話を終えたい意思と混同しない
- AIが提案した一つの行動への同意と、会話を終えることへの同意を混同しない
- 一度「続けたい」という意思を確認したら、次に終了へ向かうには改めて確認が要る
- クロージングの要約は、AIが結論を言い切らず、ユーザー自身に語ってもらう形にする

これは嶋先生インタビュー2で出た「見捨てられ感」(AIが突然「これ以上はできない」と
切ると、生徒は見捨てられる前に自分から画面を閉じる)という臨床的な裏付けとも一致します。

## データ設計への影響

### 新しい出典タグ

`02_専門プロトコル別ナレッジベース.md` の内容を `knowledge` テーブルに追加する際、
出典タグは既存の `嶋`/`石`/`嶋石`/`理`/`設` のいずれでもない、新しいタグ
(例: `技`、技法・プロトコル理論資料)を割り当ててください。出典URLは `note` カラムに
記録してください(このテーブルには既に `note text` カラムがあります)。

### モード(mode)という新しい軸の追加

既存の `knowledge.weight` (rapport/main/goal/plan) は「関わりの重心」を表す軸で、
今回追加する「モード」(CBT/SFBT/NARRATIVE/ASSERTION/LISTEN_ONLY/PROBLEM_SOLVING/
PSYCHOEDUCATION)とは別の軸です。この2つの軸をどう共存させるか、設計案を
提示してください。例えば、モード内でも関わりの型(visitor/complainant/customer)は
引き続き有効(コンプレイナント型の生徒には、SFBTモードの中でも行動を求めない、等)
という理解でよいか、あなたの案を聞かせてください。

### インテーク(フェーズ1)の実装

現在の `sessions` テーブルは `weight`/`relation` を持っていますが、
フェーズ1のインテーク(主訴カテゴリ・つらさスケール・ゴール)を保持する
カラムがありません。ここも設計案を提示してください。

## 進め方

以下の順で進めてください。一つが完了するまで次に進まないこと。

1. まず、上記の「モードという新しい軸」と「インテークの保持方法」について、
   具体的なテーブル設計案・プロンプト構造案を提示する(コードはまだ書かない)
2. 私が確認したら、DBスキーマの変更(マイグレーション)を実装する
3. 新しい出典タグのナレッジ(8技法分)を `knowledge` テーブルに投入する
4. フェーズ0(安全確認)の修正 — Tier Bの置き換え、絶望感≠危機サインの反映、
   第三者安全・いじめ対応の追加 — を実装し、安全層のテスト
   (`scripts/test-output-check.mjs` 相当)を必ず流す
5. フェーズ1(インテーク)とモード判定ロジックを実装する
6. フェーズ2(モード別プロトコル)を実装する。この時点で、既存の非構造化
   ナレッジ(嶋/石の逐語)がプロンプトにどう組み込まれるかを、実際の出力例と
   ともに示してほしい
7. クロージングロジックを、構造化プロンプト11章に沿って実装する

## 守ってほしいこと

- 技法名(CBT、SFBT等)をAIが自分からユーザーに開示しない
  (`00_統合版...txt` 8章、既存の`IS5`/`G6`と同じ原則)
- フェーズ2のどのモードでも、太字の見出しや箇条書きでの長文説明をしない。
  共感・受容(1〜2文)＋問いかけ(1文)の形を維持する
- 会話の各ターンでは、内部の判定結果(mode、safety_check等)をユーザーへの
  応答に含めない。ユーザーが明示的にログを求めた場合のみ出力する
  (`03_共通グランドルール...txt` 9章)
- 危機対応・ログレビュー画面・人単位の記憶など、これまで実装した既存機能は
  壊さないこと。変更が既存のテストに影響する場合は、その旨を報告してください
